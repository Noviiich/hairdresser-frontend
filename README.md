# Преображение

Адаптивный frontend студии красоты: авторская светлая концепция с лавандовыми акцентами, локальными изображениями и шрифтами. Чистые HTML, CSS и JavaScript, без runtime-зависимостей и CDN. Нужен Node.js 20+; `npm install` не требуется.

## Запуск

```sh
npm run dev
```

Открыть http://localhost:5173. После изменения файлов обновите страницу. Для другого порта: `npm run dev -- --port 3000`. Для доступа с телефона в своей сети: `npm run dev -- --host 0.0.0.0`.

```sh
npm test         # проверка логики записи
npm run build   # статические файлы в dist/
npm run preview # просмотр dist/ на порту 5173
```

Папку `dist/` можно разместить на любом статическом хостинге, в том числе в подкаталоге: пути к ресурсам относительные. Сервер в `scripts/dev.mjs` предназначен для локального просмотра. При работе в среде с запретом сетевых сокетов (`listen EPERM`) запустите команду в обычном локальном терминале.

## CI/CD и GitHub Pages

Workflow: [`.github/workflows/ci.yml`](.github/workflows/ci.yml). Редактировать его под название репозитория или основной ветки не нужно.

Есть два способа первого включения: **только через Secret `PAGES_TOKEN`**, либо **вообще без Secrets** с одним переключателем в настройках Pages. Дальнейшая публикация использует встроенный `GITHUB_TOKEN`, который GitHub создаёт для запуска автоматически. Сервер и SSH-ключи не нужны.

### Вариант 1: настроить только GitHub Secrets

1. Создайте **fine-grained Personal Access Token** в настройках своего GitHub-аккаунта: **Settings → Developer settings → Personal access tokens → Fine-grained tokens**. Выберите владельца репозитория и доступ **Only select repositories** только к этому репозиторию.
2. В **Repository permissions** задайте **Pages: Read and write** и **Administration: Read and write**. Эти права требуются GitHub API для первоначального включения Pages; учётная запись должна иметь право управлять Pages репозитория. См. [права для создания Pages](https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site).
3. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:

   | Secret | Значение |
   | --- | --- |
   | `PAGES_TOKEN` | Созданный выше fine-grained PAT |

4. Отправьте проект в основную ветку или запустите **Actions → CI and GitHub Pages → Run workflow** на основной ветке.

Workflow сам включит Pages, выберет публикацию через GitHub Actions и выложит собранный сайт. Если Pages уже был настроен на публикацию из ветки, при наличии `PAGES_TOKEN` источник будет переключён на GitHub Actions. После первого успешного деплоя этот Secret можно удалить: для дальнейших публикаций достаточно встроенного `GITHUB_TOKEN`.

Если организация требует одобрения fine-grained PAT или ограничивает Pages/Actions, соответствующий доступ должен быть разрешён её администратором.

### Вариант 2: без Secrets

1. Отправьте проект вместе с `.github/workflows/ci.yml` в GitHub-репозиторий.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Откройте **Actions → CI and GitHub Pages → Run workflow**, выберите основную ветку и запустите workflow. Также достаточно следующего push в основную ветку.
4. После успешного `Deploy to GitHub Pages` ссылка на сайт появится у deployment в GitHub Actions и в **Settings → Pages**. Стандартный адрес проекта: `https://<owner>.github.io/<repository>/`.

В этом варианте выбор **Source → GitHub Actions** — единственная ручная настройка хостинга. Он нужен до первого деплоя: встроенный `GITHUB_TOKEN` не включает Pages у нового репозитория автоматически. Если workflow был запущен раньше, после настройки Pages повторите его запуск.

На бесплатном тарифе GitHub Pages доступен для публичных репозиториев; для приватного репозитория требуется тариф с поддержкой Pages. Подробнее: [официальная документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### Что делает workflow

- При push в любую ветку и при pull request проверяет синтаксис JavaScript, запускает `npm test` и собирает `dist/` командой `npm run build` на Node.js 24.
- Сохраняет собранный сайт как артефакт `github-pages` на 7 дней.
- После успешной проверки публикует сайт только из основной ветки репозитория (`default branch`), включая ручной запуск на этой ветке. Pull request и остальные ветки проходят проверки без публикации.
- Обновляет сайт после каждого следующего push в основную ветку. Активный деплой не прерывается новым коммитом.
- Даёт право публикации только job `deploy`; job проверки имеет доступ к содержимому только на чтение. Версии сторонних actions закреплены по полному SHA.

У проекта нет npm-зависимостей, поэтому `npm install` / `npm ci` и кеш зависимостей не используются. Если добавите зависимости, закоммитьте lockfile и добавьте установку перед проверками. Ссылки на ресурсы относительные, поэтому сайт работает и в подкаталоге GitHub Pages без отдельного `base URL`.

## Что работает

- Адаптивная страница, мобильное меню и закреплённая кнопка записи.
- Категории услуг, подробные цены, FAQ и просмотр образов в модальном окне.
- Три шага записи: услуга, подходящий мастер и время, контакты.
- Проверка имени, российского номера телефона и подтверждения демо-режима.
- Примерное расписание на неделю, исключение прошедших часов, учёт длительности и окончания рабочего дня. Часовой пояс: Москва.
- Управление с клавиатуры, нативные диалоги с удержанием фокуса, закрытие через Escape, поддержка `prefers-reduced-motion`.
- Локальные WebP, responsive-изображение первого экрана, lazy loading остальных изображений, отсутствие трекеров.

## Перед настоящим запуском

Сейчас это **frontend-демонстрация**. Данные формы не отправляются и не сохраняются; после закрытия диалога очищаются. Завершение формы явно сообщает, что визит не забронирован. Цены, мастера и расписание — примеры; изображения созданы для концепции и не выдаются за реальные работы салона.

1. Заменить услуги и мастеров в `src/data.js`, адрес и контакты в `index.html`.
2. Подключить backend или систему записи вместо демонстрационного результата в `submitContact` (`src/app.js`), получать доступность с сервера и проверять бронирование на сервере.
3. Добавить актуальные сведения об обработке персональных данных и согласие после выбора реального механизма обработки.
4. При необходимости заменить концептуальные изображения фотографиями салона и работ.

Цвета находятся в CSS-переменных в начале `src/styles.css`. Встроенные SVG-значки не требуют библиотеки.
